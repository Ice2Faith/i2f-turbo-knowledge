## 软件质量属性

- 质量属性综述
    - 软件系统属性
        - 包括
            - 功能属性
            - 质量属性
                - 就是非功能性需求
        - 软件架构应在满足功能属性的前提下
        - 重点关注质量属性
        - 通常采用场景的方式进行描述
    - 软件系统质量属性
        - 软件系统与明确的、隐含的定义的需求相一致的程度

        - 主要关注的质量属性

### 质量属性详解

- 性能
    - 软件系统及时提供相应服务的能力
    - 即通过多长时间才能对某件事做出响应
    - 或，某段时间内能处理的事件个数
    - 测试工具
        - 基准测试程序
- 可靠性
    - 软件系统在一定的时间内持续无故障运行的能力
    - 常用表示
        - 平均失效等待时间（MTTF）
            - 坏了之后，平均需要多长时间才能恢复
        - 平均失效间隔时间（MTBF）
            - 两次故障，平均间隔多长时间
        - 注意点
            - 如果失故障时间短的话，MTTF约等于MTBF
    - 可靠性可分为两个方面
        - 容错性
            - 错误发生时，确保系统的正常行为，并进行内部修复
                - 也主要是，catch异常的处理
                - 或者是，负载到可用的节点
        - 健壮性
            - 保护程序不受错误输入和错误使用的影响
                - 也就是输入合法性校验
                - 防呆设计
            - 发生错误意外事件时确保系统处于预先定义好的状态
                - 也就是，catch捕获可能发生的异常并处理
                - 不至于程序直接崩溃
- 可用性
    - 一定时间内系统能正常运行所占时间的比例
    - 常用两次故障之间的时间长度
    - 或，出现故障时系统能够恢复正常的速度来表示
    - 表示
        - 可用时间与总时间之间的比例，用来表示可用率
        - 一般说的，达到几个9的可用性，说的就是这个
- 安全性
    - 指软件西戎同时兼顾向合法用户提供服务
    - 以及组织非授权、非法使用的能力
- 可修改性
    - 能够快速的以较高的性价比对系统进行变更的能力
    - 细分为
        - 可维护性
            - 当需要修改缺陷、增加功能、提高质量属性时
            - 识别修改点并实施修改的难易程度
            - 侧重
                - 修改缺陷
        - 可扩展性（灵活性）
            - 软件因适应新需求或需求变化而增加新功能的能力
            - 也称为，灵活性
            - 侧重
                - 增加新功能，架构不变
        - 结构重组
            - 重新组织软件系统的构件以及构件间的关系
            - 侧重
                - 系统重构方便性
        - 可移植性
            - 将软件系统从一个运行环境转移到另一个不同的运行环境的难易程度
- 功能性
    - 系统完成所期望工作的能力
    - 侧重
        - 完成用户功能性需求
- 可变性
    - 架构经扩充、变更成为新架构的能力
    - 侧重
        - 架构的演化、升级
- 互操作性
    - 系统与其他系统或软硬件环境交互的难易程度
    - 侧重
        - 功能接口是否良好、主数据是否定义、数据定义、数据标准、通用数据交换格式

### 质量属性补充知识

- 国家标准
    - 根据 GB/T 16260.1 定义
        - 软件质量影响因素可划分为6个维度特征
            - 功能性、可靠性、易用性、效率（性能）、可维护性、可移植性
        - 特征描述
            - 功能性
                - 与一组功能及其指定的性质的存在有关的一组属性
                - 功能呢是指满足规定或隐含需求的那些功能
                - 包括
                    - 适应性
                        - 与对规定任务能否提供一组功能以及这组功能是否适合有关的软件属性
                    - 准确性
                        - 与能够得到正确或相符的结果或效果有关的软件属性
                    - 互用性
                        - 与其他指定系统进行交互操作的能力相关的属性
                    - 依从性
                        - 使软件服从有关的标准、约定、法规及类似规定的软件属性
                    - 安全性
                        - 与避免对程序集数据的非授权故意或意外访问的能力有关的软件属性
            - 可靠性
                - 即与在规定时间内和规定的条件下软件为此其性能水平有关的能力
                - 包括
                    - 成熟性
                        - 与由软件故障引起失效的频度有关的软件属性
                    - 容错性
                        - 与在软件错误或违反指定接口的情况下为此指定的性能水平有关的软件属性
                    - 易恢复性
                        - 与在故障发生后，重新简历其性能水平并回复直接受影响数据的能力
                        - 以及为达到此目的所需的事件和努力有关的软件属性
            - 易用性
                - 即与为使用所需的努力和由一组规定或隐含的用户对这样使用所做的个别评价有关的一组属性
                - 包括
                    - 易理解性
                        - 与用户为理解逻辑概念及其应用所付出的劳动有关的软件属性
                    - 易学性
                        - 与用户为学习器应用（如操作控制、输入、输出）所付出的努力有关的软件属性
                    - 易操作性
                        - 与其他制定系统进行交互操作的能力相关的属性
            - 效率（性能）
                - 即与在规定条件下，与软件的性能水平与所用资源量之间的关系有关的软件属性
                - 包括
                    - 时间特性
                        - 与响应和处理事件以及软件执行其功能时的吞吐量有关的软件属性
                    - 资源特性
                        - 与软件执行其功能时，所使用的资源量以及使用资源的持续时间有关的软件属性
- 软件质量属性概念
    - 软件质量属性是描述系统满足毅力相关者需求的可测量或可测试的属性
    - 质量属性分为
        - 开发期质量属性
            - 易理解性
            - 可扩展性（灵活性）
            - 可重用性
            - 可测试性
            - 可维护性
            - 可移植性
        - 运行期质量属性
            - 性能
            - 安全性
            - 可伸缩性
            - 互操作性
            - 可靠性
            - 可用性
            - 鲁棒性（容错性）
                - 指软件系统在非正常情况下仍能够正常运行的能力
                - 也称，健壮性、容错性

### 质量属性场景描述

- 质量属性场景（4+1的1）
    - 是一个具体的质量属性需求
    - 是利益相关者与系统交互的简短描述
    - 主要关注可用性、可修改性、性能、可测试性、易用性、安全性等6类质量属性
    - 组成方面
        - 刺激源
            - 生成该刺激的实体（人、系统、其他刺激器）
        - 刺激
            - 当刺激到达系统时需要考虑的条件
            - 举例
                - 执行了什么操作
        - 环境
            - 该刺激在某条件内发生
            - 当激励发生时，系统可能处于过载、运行或其他情况
        - 制品
            - 某个制品被激励，可能是整个系统，也可能是系统的一部分
        - 响应
            - 激励到达后采取的行动
            - 举例
                - 操作之后发生了什么
        - 响应度量
            - 当响应发生时，以某种方式对其进行度量，以对需求进行测试
    - 一般是关键业务路径上进行考虑
    - 表示形式
        - 也就是通过表格形式
        - 描述上面各个组成部分
        - 形成一个多行两列的表格
        - 每一个这样的表格就可以表示一个质量属性场景
    - 分类
        - 可用性质量属性场景
            - 关注的方面包括系统故障发生的频率
            - 出现故障时会发生什么情况
            - 允许系统有多长时间非正常运行
            - 什么时候可以安全地出现故障
            - 如何防止故障的发生
            - 发生故障时要进行哪种通知
        - 可修改性质量属性场景
            - 关注系统在改变功能、质量属性时需要付出的成本和难度
            - 可能发生在系统设计、编译、构建、运行等多种情况和环境下
        - 性能质量属性场景
            - 关注系统的响应速度
            - 可以通过效率、响应时间、吞吐量、负载来客观评价性能的好坏
        - 易用性质量属性场景
            - 关注用户使用系统时的容易程度
            - 包括系统的学习曲线、完成从操作的效率、对系统使用过程的满意程度等
        - 可测试性质量属性场景
            - 关注系统测试过程中的效率
            - 发现系统缺陷或故障的难易程度
        - 安全性质量属性场景
            - 关注系统在安全性方面的要素
            - 衡量系统在向合法用户提供服务的同时，组织非授权、非法用户使用的能力

### 软件质量影响因素

- 软件质量
    - 就是软件与明确地、隐含地定义的需求相一致的程度
    - 更具体地锁
    - 是软件符合明确地叙述的功能和性能需求
    - 文档中明确描述的开发标准以及所有专业开发的软件都应具有的隐含特征的程度
- 影响因素
    - 从管理角度出发，可以将影响软件质量的因素划分为3组
    - 分别反映用户在使用软件产品时的3中不同倾向和观点
    - 分别是
        - 产品运行
            - 正确性
                - 它按我的需要工作吗
            - 健壮性
                - 对意外环境它能适应地响应吗
            - 效率
                - 完成预定功能时它需要的计算机资源多吗
            - 完整性
                - 它是安全的吗
            - 可用性
                - 我能使用它吗
            - 风险
                - 能按预定计划完成它吗
        - 产品修改
            - 可理解性
                - 我能理解它吗
            - 可维护性
                - 我能修复它吗
            - 灵活性
                - 我能改变它吗
            - 可测试性
                - 我能测试它吗
        - 产品转移
            - 可移植性
                - 我能在另一台机器上使用它吗
            - 可再用性
                - 我能再用它的某些部分吗
            - 互运行性（互操作性）
                - 我能把它和另一个系统结合吗
